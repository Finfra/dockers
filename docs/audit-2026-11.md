# 개요

* 대상: git 추적 Dockerfile 26개(`Dockerfile`·`Dockerfile.*`)와 docker-compose 파일 20개
* 점검 항목
    - EOL(지원 종료) 베이스 이미지
    - 태그 미고정(무태그·`latest`·이동 태그)
    - 불필요한 root 실행
    - 패키지 캐시 미정리(apt lists·pip·npm 캐시)
    - 노출된 기본 비밀번호·비밀 정보
* 원칙: 교육용 예제라 **동작을 바꾸는 변경(베이스 OS 교체·태그 고정·비밀번호 제거 등)은 이번에 하지 않았다** — 아래는 권고다
* 이번에 직접 고친 것(동작 불변)
    - `.dockerignore` 신설 6곳: `claude`·`ollama-claude`·`lms_cc_all`·`vllm_qwen38`·`ubuntu_ssh/docker`·`ubuntu_ssh_provisioner/docker` (COPY 하지 않는 `.env`·개인키·마운트 폴더·로그 제외)
    - Dockerfile 주석 오류: `wordpress_adv*/wpDb1/Dockerfile`, `ubuntu_ssh/docker/Dockerfile`
    - README 의 틀린 명령: `docker compose exec` 대상을 서비스명으로(oracle-linux_ssh·ubuntu_ssh), wordpress_adv 접속 URL https→http, springBoot_gradle 이미지 정리 grep, v1 `docker-compose` 호출 → v2 `docker compose`
* README 가 없는 폴더: 없음 (예제 폴더 27개 + `tdd` 모두 README 보유) — 신설하지 않음

# 공통 권고

* **태그 고정**: 무태그·`latest` 는 빌드 시점마다 결과가 달라진다. `nginx` 폴더처럼 버전 태그로 고정하고(재생목록 `nginx-pinned` 와 같은 방식) 전 폴더 대상 테스트로 확장
* **`MAINTAINER` → `LABEL maintainer=...`** (8개 파일, 동작 영향 없음)
* **apt 정리 패턴 통일**: `apt-get update && apt-get install -y --no-install-recommends ... && rm -rf /var/lib/apt/lists/*` 를 한 RUN 에서. `apt` 대신 `apt-get`
* **pip·npm 캐시**: `pip install --no-cache-dir`, `npm install -g ... && npm cache clean --force`
* **파이프 RUN**: `SHELL ["/bin/bash", "-o", "pipefail", "-c"]` 선언 — `curl ... | bash` 실패가 빌드 실패로 드러나게
* **원격 설치 스크립트 고정**: `curl | bash`(nodesource·lmstudio·sdkman), `npm install -g @anthropic-ai/claude-code`, wp-cli phar 은 버전 인자를 노출(`ARG`)해 재현성 확보
* **포트 바인드**: 학습용 SSH·DB·LLM API 포트가 `0.0.0.0` 으로 열린다. `lms_cc_all` 처럼 `127.0.0.1:` 기본값을 두고 필요할 때만 넓히는 방식을 권장
* **compose `version:` 키**: Compose v2 에서 무시되며 경고를 낸다(apacheSsl·wordpress) — 삭제 권장

## centos7_user
* **EOL**: CentOS 7 은 2024-06-30 지원 종료. 기본 미러(mirrorlist.centos.org)도 내려가 이미지 안에서 `yum install` 이 실패한다. 교육 목적 유지가 필요하면 README 에 EOL 경고를 두고, 신규 실습은 `oraclelinux:9`·`rockylinux:9`·`almalinux:9` 계열 폴더로 유도
* `MAINTAINER` 폐기, `CMD /start.sh` → `CMD ["/start.sh"]`
* `start.sh` 가 비밀번호를 표준출력에 그대로 찍는다(`start.sh` 마지막 echo 줄) — 로그에 남는다
* `ENV LC_ALL en_US.UTF-8` 레거시 문법 → `ENV LC_ALL=en_US.UTF-8`
* Dockerfile 상단 "Fedora-Dockerfiles 에서 포팅" 저작 주석은 현재 내용과 무관해 보임 — 출처 확인 후 정리

## oracle-linux_ssh
* **root 고정 비밀번호(Dockerfile `chpasswd`) + `PermitRootLogin yes` + `PasswordAuthentication yes`**, 포트 `22222` 전 인터페이스 공개 — 같은 네트워크의 누구나 root 로그인 가능. 최소한 `127.0.0.1:22222:22` 바인드 또는 키 인증 전용 + 비밀번호 빌드 인자화 권장
* 연속 RUN 통합, `dnf` 버전 미고정(교육용이면 허용)
* `root/` 아래 `.viminfo`·`known_hosts` 등 개인 사용 흔적이 추적 중 — 정리 검토

## pyspark-notebook
* `quay.io/jupyter/pyspark-notebook:latest` → 날짜·Spark 버전 태그 고정 권장
* 같은 폴더의 `install.sh` 는 Dockerfile 에서 쓰지 않는다(구버전 잔재, 종료된 bintray 저장소·`libpng12` 참조) — 삭제 또는 `legacy` 표시 권장
* NB_USER NOPASSWD sudo — 기존 동작 보존 목적이라 명시됨

## pyspark-tensorflow-notebook
* `jupyter/pyspark-notebook` 무태그 — Jupyter 프로젝트는 Docker Hub 이미지 갱신을 중단하고 `quay.io/jupyter` 로 옮겼다. `pyspark-notebook` 폴더처럼 quay.io + 고정 태그로 전환 권장
* `chmod 777 /etc/sudoers` 후 append 하는 방식 → `/etc/sudoers.d/` 파일 방식(pyspark-notebook 폴더 참고)
* `PYTHONPATH` 의 `py4j-0.10.7`, `MESOS_NATIVE_LIBRARY` 는 현재 이미지와 맞지 않을 가능성이 큼 — 확인 후 정리
* `install.sh`: `pip install ... sklearn` 은 폐기된 패키지명이라 설치가 실패할 수 있고, 스크립트에 `set -e` 가 없어 실패가 빌드 실패로 드러나지 않는다 → `scikit-learn` + `set -e` 권장. apt·pip 캐시 미정리
* `MAINTAINER` 폐기
